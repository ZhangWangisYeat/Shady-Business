# Shady Business — UCLA-only shade model blueprint

**This is the implementation design for the hackathon, not a claim that a UCLA shade surface has already been computed.** Treat campus scope as a strength: precompute a small, auditable environment once; focus live compute on changing solar angles and route weights.

## Data interface (prefer optional-source adapters)
- `ucla_walk.graphml` generated by existing OSMnx script, verified against official UCLA accessibility paths.
- `ucla_trees.geojson`: GeoJSON Points with `height_m`, `crown_radius_m`, `source`, `capture_date`, `confidence`, optional `live_crown_ratio`; may originate from permitted UCLA ArborPro export. Do **not** interpolate a numeric height where none exists.
- `ucla_buildings.geojson`: polygons with optional `height_m`, `height_method` (`measured`, `osm_height`, `levels_estimate`, `unknown`), source/license. Start with OSM; do not automatically ingest restricted LARIAC buildings.
- `canopy.tif`: optional separate 2024 canopy coverage layer **only if rights confirmed**; this has crown extent but not per-tree height.
- `terrain.tif`: optional USGS bare-earth DEM after exact UCLA coverage confirmed.

## One-day algorithmic approach
1. Project GPS WGS84 coordinates to a local meter-based CRS (EPSG:26911) using `pyproj`. Avoid latitude/longitude geometry buffers or mixing feet with meters.
2. For the selected `America/Los_Angeles` timestamp, calculate solar elevation `alpha` and azimuth `A` via Astral/pvlib. Normalize to correct day/timezone. Sun below horizon = zero direct sunlight; do not attempt shadows when `alpha <= 0`.
3. **Buildings:** for a polygon with known height `h` and approximately flat terrain, calculate shadow offset opposite the sun at length `h / tan(alpha)`; sweep the footprint from 0 to that offset to create a first-order shadow footprint. Treat facade and setback height differences as uncertainty. Include immediate footprint area as obstructed, but route graph must not pass through building interiors.
4. **Trees:** use real stem coordinates, measured total height and crown spread; approximate crown silhouette (circle/ellipse), live-crown position, and an offset opposite the sun. Shadow projected at crown elevation is a simplification; vary assumptions and report lower confidence. Where measured crown values are missing, leave that feature unmodeled/uncertain rather than fabricate canopy dimensions.
5. Use geometry spatial indexes to sample candidate pedestrian-edge lines at 2–5 m intervals; classify each sample as modeled shade, sun, or unknown based on whether required geometry/coverage is trustworthy. Preserve provenance per segment. Overlap of several shadows still counts as shade once, not additive sunlight savings.
6. Edge walking time `t = edge_length / walking_speed` (explicit default 1.25 m/s). Edge direct-sun seconds = `t × fraction_of_known_samples_in_sun`; track **unknown seconds separately**, never as zero. Start with departure-time shadows; improve with time buckets only if everything else works.
7. **Fastest:** shortest walking time on connected pedestrian graph. **Recommended:** rank plausible candidates with `J = duration_seconds + lambda(temp_C) × known_sun_seconds`, with a small hot-weather detour cap. At sufficiently cool temperatures `lambda=0`, Recommended equals Fastest. **Most Shade:** minimize direct-sun seconds within a stricter hard maximum walking-time detour; prevent circular/disconnected routes.
8. Existing backend searches time-shortest candidates, so it may MISS a very shady detour. A more complete weighted/multiobjective candidate search is needed before claiming global optimality. For MVP, compare bounded candidate set transparently and test on a few manually checked campus journeys.

## Most likely challenge (and practical fix)
**A campus pedestrian polyline is not always a sidewalk centerline.** East/west campus paths and stairs, courtyards, plazas, building overhangs and slopes mean the actual exposure may differ from centerline samples. For the demo, select two well-defined pedestrian corridors near Royce/Powell/Kerckhoff; sample corridor width/side on a short field walk. This is more valuable than trying to map every campus path overnight.

## Weekend gates: facts that must be checked before claiming shade accuracy
- Tree measurements available under a usable permission and with known coordinate CRS, or independent shadow geometry sourced elsewhere.
- Buildings near demo route have actual/traceable height fields; label `building:levels` as inferred.
- Check output against 8–12 timed site observations at 9 AM/noon/late afternoon (or actually available times).
- Compare route calculations on 3 preselected origin–destination pairs; record `fastest_seconds`, `recommended_seconds`, `most_shade_seconds`, `sun_seconds`, `unknown_seconds`.
- No invented current UV index, clouds, surface temperatures, tree foliage density, or medical risk probabilities.

## Performance architecture
- Offline preprocessing (OSM graph, licensed trees/buildings and projected geometries) as a **one-time campus build step**. Pack processed source assets only when licenses allow; prefer local `backend/data/` ignored by Git.
- Cache the immutable campus walk graph and static obstacle geometries in FastAPI memory.
- Solar angle is cheap to compute; for a chosen time bucket, calculate shadow polygons only around candidate edges, not all LA.
- Frontend receives genuine GeoJSON route segments and shade classifications and never needs to download lidar or raw image rasters.
- Do not add an LLM step to the deterministic routing loop. A vision model might assist with missing crown detection later, with permission and evidence.
